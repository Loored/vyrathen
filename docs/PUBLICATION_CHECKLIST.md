# Vyrathen — Lista previa al primer push público

- [ ] El código, README, título y `package.json` muestran sólo la marca Vyrathen en el producto.
- [ ] **No** hay material de Wayback, archivos `.private/`, informes con autores/jugadores, fotos, música o imágenes de terceros subidos.
- [ ] No se incluye el árbol gráfico original; diseñar una alternativa propia antes de habilitar el sistema visual.
- [ ] Revisar los nombres/descripciones de habilidades de la alfa: algunos proceden de mecánicas históricas y siguen siendo **provisionales**; verificar derechos antes de un lanzamiento o aprovechar para renombrarlos creativamente.
- [ ] Decidir licencia de código conscientemente. **No** se añadió licencia de manera automática; sin licencia no se conceden automáticamente permisos de reutilización a terceros.
- [ ] Revisar marca Vyrathen (IMPI, OMPI y jurisdicciones de distribución); nombre de repositorio disponible ≠ registro de marca.
- [ ] Revisar `git status`, `git add -n .` y `git diff --cached --stat` antes del commit. Nunca usar `git add -f .private`.
- [ ] `npm install`, `npm test`, `npm run typecheck`, `npm run build` y revisión visual en navegador antes del release.
- [ ] No subir secretos ni credenciales. Comprobar `.env*` y scripts externos.

Los documentos de investigación están separados para uso privado. Esta lista es una precaución técnica, no una revisión jurídica definitiva.
